# 记忆归档

回顾本次对话，将值得记住的信息写入 `~/.claude/user-memory/` 下的记忆文件。

**核心目标**：记忆持久化 + 人物画像精确化 + 助理定位进化

## 步骤

### 1. 加载现有记忆

读取以下文件，了解当前记忆状态（避免重复写入）：

- `~/.claude/user-memory/self.md`
- `~/.claude/user-memory/profile.md`
- `~/.claude/user-memory/working.md`
- `~/.claude/user-memory/journal/YYYY-MM.md`（当月，不存在则创建）
- `~/.claude/user-memory/learning/overview.md`（如存在）

### 2. 回顾对话，提取信息

从本次对话中提取以下类别的信息：

**→ profile.md（人物画像 - 优先级最高）**

**重点检查以下维度是否有新信息：**

| 维度 | 优先级 | 检查问题 |
|------|--------|----------|
| **认知框架** | ★★ | 新的分析方法、思维模型、因果链条？（如：权力→资源→货币、三层分析框架） |
| **核心驱动力** | ★★ | 对"为什么想做某事"的新理解？世界观的深化？ |
| 关注领域 | ★ | 新的兴趣方向？原有兴趣的深化/转向？ |
| 身份 | ★ | 职业、学历、状态是否有变化？ |
| 技术栈 | ★ | 新增/删除语言、框架、工具？ |
| 偏好 | ★ | 通过判断表达的选择倾向？（如："XX更高效""这样不合理""XX是核心"） |
| 性格 | ★ | 新的行为模式、决策风格观察？ |

**注意**：通过**分析和判断**——关注主人对事物有效性、合理性的评价。

**→ self.md（助理定位 - 可进化）**

- 用户对助理行为的校正或期待 → 更新行为原则
- **助理的角色定位可以随对话深化而精炼**——如果用户表达了对助理功能的重新理解，更新"我是什么"或"我和主人的关系"段落
- 记忆原则的校正 → 直接覆盖更新

**→ working.md（活跃事项）**

- 新开始的项目或任务 → 添加到"进行中"
- 已完成的事项 → 添加到"最近完成"并标日期
- 卡住或等待中的事项 → 添加到"等待/阻塞"
- 完成超过 7 天的条目 → 归档到 journal

**→ learning/（学习进度）**

- 对话涉及学习/教学活动 → 读取对应学科文件，更新进度
- 用户调整学习策略 → 更新 overview.md
- **仅在实际发生学习活动时更新**

**→ journal/YYYY-MM.md（月度归档）**

- 追加一条当日摘要（概括本次对话做了什么）
- 格式：`## MM-DD` 下追加条目

### 3. 写入更新

- 只记用户明确说的或对话中实际发生的，不推测不脑补
- **profile.md 有新信息必须更新**——这是人物画像持续精确化的核心
- **认知框架和核心驱动力优先记录**——这些是理解主人思维的关键
- 覆盖更新已有条目，不重复追加
- 记忆冲突时以最新信息为准
- 纯技术编程对话只需在 journal 记一笔摘要
- 如果对话中没有值得记忆的信息，告知用户"本次对话无需归档"

### 4. raw/ 原始对话记录（可选）

判断本次对话是否有值得完整保留的深度讨论（如：认知框架推演、重大决策审计、方法论洞察）。如果有：

1. **先询问用户**："本次对话要写 raw 吗？"
2. 用户明确同意后，才写入 `~/.claude/user-memory/raw/YYYY-MM-DD-主题.md`
3. 内容：一比一还原对话关键段落 + 助理看法/分析
4. **不主动写入，不默认写入**

### 5. Git 提交

在 `~/.claude/user-memory/` 目录执行：
1. `git add` 所有变更的记忆文件
2. `git commit -m "描述"`，commit message 用中文概括本次归档内容

### 6. 汇报结果

用简洁的列表告知用户更新了哪些文件、更新了什么内容。格式示例：

```
记忆已归档：
- profile.md：新增"权力→资源→货币→经济"认知链条、补充三层分析框架
- journal/2026-03.md：添加 03-24 摘要（AI 时代教育讨论）
```

如无更新则回复：本次对话无需归档。
